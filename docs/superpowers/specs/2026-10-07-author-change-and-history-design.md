# Смена автора тикета и история карточки

Дата: 2026-10-07. Статус: черновик на ревью.

## Цель

1. Менять «кто поставил задачу» (автора) у уже созданного тикета.
2. В карточке открывать окно «История» со всеми событиями тикета: кто создал, кто и на кого что менял, комментарии.

## Решения (согласовано в чате)

- Автора могут менять все, кто может создавать тикеты: `canCreate` (`isCreator`). Суперадмина отдельно не добавляем.
- Новый автор обязан быть участником чата доски.
- Историю для старых тикетов не восстанавливаем: у них будет одно событие «создан» (по `createdAt` и `authorId`), полная история пойдёт с момента выката.
- Комментарии показываются в ленте истории вместе с событиями, в хронологическом порядке.
- Новому автору уведомление не отправляется. Дальше статусные уведомления (`notifyAuthorStatus`) идут уже ему.

## Права

`src/domain/permissions.ts`: `canChangeAuthor(a: Actor) = canCreate(a)`. Отдельная функция нужна, чтобы правило можно было менять независимо и проверять тестами.
В `CardView` добавляется флаг `canChangeAuthor`, клиент по нему показывает или прячет выбор автора. Проверка на сервере обязательна.

Побочный эффект, который принимаем: смена автора меняет, кто может править текст и удалять тикет (`canEditText`, `canDelete`). Это ожидаемо и входит в семантику «автор».

## Данные

Новая таблица `task_events` (миграция Drizzle `npm run db:generate`):

| колонка | тип | примечание |
|---|---|---|
| id | bigserial PK | |
| task_id | bigint | FK `tasks.id`, `on delete cascade`, индекс |
| actor_id | tg id, nullable | FK `users.id`; пусто для системных событий |
| type | text | см. ниже |
| payload | jsonb | значения «было → стало» |
| created_at | timestamptz | `defaultNow()` |

Типы событий и `payload`:

- `created`: `{ author: string, assignees: string[] }`
- `status`: `{ from: Status, to: Status }`
- `author`: `{ from: string, to: string }`
- `assignees`: `{ from: string[], to: string[] }`
- `stars`: `{ from: number, to: number }`
- `deadline`: `{ from: string, to: string }`
- `text`: `{ from: string, to: string }`
- `blocked`: `{ reason: string }`
- `unblocked`: `{ reason: string | null }`

В payload пишутся имена-снимки (`displayName` на момент события), а не id: переименование или удаление пользователя не меняет историю.

Комментарии остаются в `comments`, в `task_events` не дублируются. Лента строится слиянием событий и комментариев по `createdAt`.

Системный комментарий «Разблокировано. Причина была…» больше не создаётся: его заменяет событие `unblocked`. Старые системные комментарии остаются в данных и выводятся в ленте как есть.

## Сервер

- `src/server/events.ts`: `recordEvent(tx, { taskId, actorId, type, payload })` принимает транзакцию, чтобы событие и изменение записывались атомарно. `loadHistory(taskId)` возвращает слитую ленту.
- Вызовы `recordEvent`:
  - `createTask`: `created`;
  - `moveTask`: `status`, если статус изменился (в том числе автоснятие блокировки даёт `unblocked`);
  - `updateTask`: по одному событию на каждое реально изменившееся поле (`text`, `stars`, `deadline`, `assignees`, `author`); события без изменения значения не пишутся;
  - `blockTask`: `blocked`; `unblockTask`: `unblocked`.
- `TaskPatch` получает `authorId?: number`. В `updateTask`: проверка `canChangeAuthor`, проверка членства нового автора в чате (`listMembers`), иначе `AccessError` (403 и 400 соответственно). Запись в `tasks.authorId` и событие `author` в одной транзакции.
- Новый маршрут `GET` истории карточки по образцу существующих маршрутов задач, с теми же проверками `canView`. Ответ: `HistoryItem[]`.
- `boardVersion` не меняется: любое изменение уже двигает `tasks.updatedAt`.

## Домен (чистая логика, без I/O)

`src/domain/events.ts`:

- типы `EventType`, `TaskEvent`, `HistoryItem`;
- `formatEvent(event): string`: русский текст события без имени исполнителя («сменил исполнителей: А, Б → В», «перенёс в In progress», «изменил дедлайн: 2026-10-08 → 2026-10-10»);
- `mergeHistory(events, comments): HistoryItem[]`: сортировка по `createdAt`, затем по id.

Покрывается юнит-тестами `events.test.ts` (`npm test`). Даты форматируются в `Asia/Almaty`, тексты на русском.

## UI (Mini App)

- `CardSheet.tsx`: блок автора. Для `card.canChangeAuthor` это пикер участников чата в стиле выбора исполнителей (одиночный выбор), иначе текст, как сейчас.
- Кнопка «История» в карточке открывает модальное окно. Данные подгружаются при открытии. Строка ленты: время, автор действия, текст события; комментарии выводятся с текстом. Пустая и ошибочная загрузки обрабатываются отдельно.
- Стили в существующих CSS-модулях, без новых зависимостей. Если у `CardSheet` уже есть паттерн модалок, используем его.

## Ошибки

Запись события идёт в той же транзакции, что и изменение, поэтому состояния «изменилось, а истории нет» не бывает. Загрузка истории не влияет на остальную карточку: при ошибке окно показывает сообщение и кнопку повтора.

## Тестирование

- Юнит: `canChangeAuthor` в `permissions.test.ts`; `formatEvent` и `mergeHistory` в `events.test.ts`.
- `npm run typecheck`, `npm run build`.
- Ручная проверка в Mini App: смена автора создателем и отказ для не-создателя, запись событий при каждом изменении, окно истории.

## Вне объёма

Восстановление истории старых тикетов, уведомления о смене автора, показ истории в админке, фильтры и пагинация ленты (лента одной карточки небольшая).
