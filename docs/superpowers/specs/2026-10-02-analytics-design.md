# Аналитика доски — дизайн

Дата: 2026-10-02 · Статус: на ревью

## Цель

Дать участникам группы обзорный экран по доске: сколько и какой сложности задач закрыто, кто их закрыл, укладываемся ли в сроки. Главный вопрос пользователя — «какие задачи по какой сложности закрыто».

Основа — метрики потока из Kanban Guide (throughput, время до закрытия) и throughput, взвешенный по оценке (сумма звёзд — аналог story points в Jira).

## Решения

- Вариант «всё понемногу»: KPI сверху, затем три блока графиков, вертикальная прокрутка.
- Аналитику видит тот же круг, что и доску (`canView`). Отдельной роли нет.
- Только существующие данные, без миграций. Время считается «создание → закрытие» (lead time); «в работе → закрытие» не считаем — момент взятия в работу не хранится.
- Графики рисуем сами (div/SVG), без новой библиотеки.

## Данные и определения

Закрытая задача — `status = 'done'` и `doneAt` попадает в период. Возврат из Done сбрасывает `doneAt`, такая задача из статистики выпадает до повторного закрытия.

Период — последние 7, 30 или 90 дней по `Asia/Almaty`, включая сегодня. По умолчанию 30. Для дельт KPI берётся предыдущий период той же длины.

- **Закрыто** — число закрытых задач.
- **Звёзды** — сумма `stars` закрытых задач.
- **Вовремя** — доля закрытых, у которых дата закрытия (Алматы) ≤ `deadline`. В процентах, округление до целого.
- **Дней до закрытия** — медиана целых дней между датой создания и датой закрытия (Алматы), по каждой сложности.
- **По людям** — для каждого исполнителя закрытые задачи, разбитые по звёздам. Задача с несколькими исполнителями засчитывается каждому; задачи без исполнителя — строка «Без исполнителя». Подпись под блоком: «Задача с несколькими исполнителями учитывается у каждого».

Корзины графика темпа: для 7 дней — по дням, для 30 и 90 — по неделям (понедельник–воскресенье, Алматы). Первая и последняя неделя могут быть неполными.

## Экран

Кнопка с иконкой графика в шапке доски, слева от «Обновить» (`aria-label="Аналитика"`). Открывает экран аналитики поверх доски; Telegram BackButton возвращает на доску.

Сверху вниз:
1. Заголовок «Аналитика» + название доски, переключатель периода `7 дн · 30 дн · 90 дн`.
2. Три KPI-карточки: Закрыто, Звёзды, Вовремя. Под числом — изменение к прошлому периоду (`+3`, `−12%`), зелёным/красным; при нуле в прошлом периоде дельта не показывается.
3. «Темп»: столбики по корзинам, каждый разбит по сложности ★1…★5; подписи дат под осью; тап по столбику показывает расшифровку.
4. «По сложности»: пять строк ★1…★5 — число закрытых, горизонтальная полоса доли, медиана дней.
5. «По людям»: аватар, имя, горизонтальная полоса с разбивкой по звёздам, справа `N задач · M ★`. Сортировка по сумме звёзд.

Цвета сложности — последовательная шкала одного оттенка (★1 светлый → ★5 насыщенный), проверенная в светлой и тёмной теме; легенда под «Темпом».

Пустое состояние: «За этот период закрытых задач нет» вместо графиков; KPI показываются с нулями.

## Архитектура

- `src/domain/analytics.ts` — чистая функция `buildAnalytics(tasks, { days, now })` → `AnalyticsView`. Вход: закрытые задачи двух периодов (`stars`, `createdAt`, `doneAt`, `deadline`, исполнители). Все расчёты здесь, покрыты юнит-тестами.
- `src/domain/types.ts` — тип `AnalyticsView`.
- `src/server/analytics.ts` — `loadAnalytics(chat, days)`: один запрос задач с `doneAt ≥ начало предыдущего периода` + исполнители (как в `loadBoard`), затем `buildAnalytics`.
- `GET /api/app/chats/[chatId]/analytics?days=7|30|90` — те же проверки, что у `board` (`requireTgUser`, `getChat`, `canView`). Неверный `days` → 400.
- `src/miniapp/Analytics.tsx` — экран; `Board.tsx` — кнопка и переключение на экран; иконка `IconChart` в `icons.tsx`; стили в `miniapp.module.css` (с явными `composes`, см. особенность Turbopack).

## Ошибки

Ошибка загрузки — текст ошибки и кнопка «Повторить». Права проверяются на сервере; клиент ничего не фильтрует.

## Проверка

- Юнит-тесты `analytics.test.ts`: границы периода по Алматы, корзины по дням и неделям, «вовремя» на границе дедлайна, медиана (чёт/нечёт), задача с двумя исполнителями, без исполнителя, пустой период, дельты.
- `npm run typecheck`, `npm test`, `npm run build`.
- Скриншоты экрана (светлая/тёмная тема, пустое состояние) пользователю до деплоя.

## Вне объёма

Время «в работе», журнал смены статусов, экспорт, фильтр по исполнителю внутри аналитики, аналитика по всем доскам сразу.
